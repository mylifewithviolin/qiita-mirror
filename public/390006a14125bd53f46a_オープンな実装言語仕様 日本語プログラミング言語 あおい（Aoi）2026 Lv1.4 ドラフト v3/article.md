# 日本語プログラミング言語あおい（Aoi）とは
システムエンジニア兼デベロッパー的な職域の人材が利用することを想定した日本語トランスコンパイラ言語です。

今日のシステム開発言語の多様化に鑑みて、それらの言語環境との相互運用性を容易としプログレッシブな導入を実現するため、他のプログラミング言語をターゲット言語とするトランスコンパイラとして実装することを推奨しています。

制御構文の開始シンボルとして、◇、〇、・、□などの全角記号を用い、箇条書きされた日本文としての体裁を[日本語プログラミング言語あおい三姉妹](

# 日本語プログラミング言語 あおい（Aoi）言語仕様 2026 Lv1.4 ドラフト v3

> この文書は、Lv1.4ドラフトv2の確定方針を維持しながら、Lv1.3にあった構文例を、現在の規則に合う形へ整えて復活させたものです。構文の種類は、できるだけ日本語の見出しで示しています。対応表案は、確定方針を具体化するための案です。

## 1. 目的と位置付け

日本語プログラミング言語あおい（Aoi）は、日本語を基調とするソースから複数のプログラミング言語へ変換するための言語仕様です。実装言語や処理系を限定せず、コンパイラ・トランスコンパイラを実装できます。

本仕様では、あおいの構文と意味を定めます。CLI、ファイル形式、診断、生成物の受入方法など、処理系固有の約束は「処理系契約」として言語仕様と区別します。将来、処理系契約を別文書へ移す場合も、本書に記載するMVP契約との相互参照を維持してください。

あおいはRe:Mind言語ファミリーの一言語です。Re:Mindをあおいの別名として構文規則に用いません。

### 1.1 規範性の表示

| 表示 | 意味 |
|---|---|
| **確定（MVP）** | MVP詳細要件と完了レポートで決定され、C#・Java・VB.NETで受入済みの規則です。MVPプロファイルに対して規範的です |
| **確定（Lv1.4方針）** | Lv1.4ドラフトの推奨案を採用した方針です |
| **対応表案** | 確定した方針を具体化するためのターゲット対応表・細則案です |
| **対象外（MVP）** | MVPの受入範囲外です。未実装・未検証であることを意味しません |

### 1.2 ターゲット中立性の二軸

あおいでは、MVPの実装範囲と、言語設計上のターゲット依存性を別の軸として扱います。

**軸1：MVPの実装範囲**

| ターゲット群 | MVPでの扱い |
|---|---|
| 静的クラスオブジェクト指向言語（C#・Java・VB.NET） | MVPの実装・受入対象です |
| それ以外の言語 | MVPの実装対象外です。ただし、将来の設計・対応対象から除外するものではありません |

「静的クラスオブジェクト指向言語」とは、静的型付けでクラスを基本単位とするオブジェクト指向言語を指します。現在MVPで受入済みの対象はC#・Java・VB.NETです。

**軸2：言語全体の設計方針**

| 言語の組み合わせ | 方針 |
|---|---|
| 静的クラスOOP言語どうし | `■インポートする` に関係する記述を除き、同じあおいソースを同じ意味に変換します |
| 静的クラスOOP言語と他の言語 | ターゲット依存を許容します |
| 静的クラスOOP言語ではない言語どうし | 依存性をなるべくなくし、共通の構文・意味を持つプロファイルを設けます |

ターゲット言語の構文を利用する箇所では、依存する範囲と、対応していないターゲットへの変換時に診断する条件を明示します。Import以外の箇所にターゲット言語の構文を無印で混在させません。

## 2. 構文層とプロファイル

### 2.1 構文層

クラスを必要としない言語中核の上に、段階的にクラス機能を追加する層構成を採用します。上位層は下位層の構文を含みます。処理系は入力に現れる構文層を判定し、選択したターゲットが対応しない層を要求されたときは、コード生成前に診断します。

| 層 | 構文の範囲 | 対応ターゲットの方針 |
|---|---|---|
| **層0：中核（クラスなし）** | 変数・定数、基本型、式、分岐・繰り返し、関数・戻り値、組込み関数 | 静的クラスOOP言語群と、非静的クラスOOP言語群の共通基盤です |
| **層1：クラス（継承なし）** | クラス、フィールド、インスタンスメソッド、インスタンス生成 | 静的クラスOOP言語、およびクラス相当機能に対応する言語が対象です |
| **層2：クラス（完全）** | 継承、`static` と `instance`、アクセス修飾子、コンストラクタ連鎖など | 静的クラスOOP言語が対象です |
| 層と独立：取込・別名定義 | `■インポートする`、`▼` によるターゲットAPI宣言 | 常にターゲット依存です |

**対応表案：ターゲット群と対応層**

次の表は、各ターゲットの将来の適合範囲を検討するための案です。MVP受入済みなのはC#・Java・VB.NETです。それ以外の行は、実装・適合性試験による確認が必要です。

| ターゲット | 想定する群 | 推奨する対応層 | 補足 |
|---|---|---:|---|
| C# | 静的クラスOOP | 層2 | MVP受入済みです |
| Java | 静的クラスOOP | 層2 | MVP受入済みです |
| VB.NET | 静的クラスOOP | 層2 | MVP受入済みです |
| TypeScript | クラス機能を持つ構造的型付け言語 | 層1（層2は機能ごとに判定） | `static`・継承の記法はありますが、型付け・実行モデルの差を考慮します |
| Go | クラスを持たない静的型付け言語 | 層0（メソッド等は別途適合判定） | structとメソッドを層1相当と認めるかは、適合試験後に確定します |
| VBA | クラスモジュールを持つ言語 | 層1 | 継承を含む層2は対象にしません |
| Mind・なでしこ | クラスを基本単位としない日本語言語 | 層0 | 各言語の型・制御構文との対応確認が必要です |
| プロデル | 日本語プログラミング言語 | 層0（初期案） | クラス機能を含む構文は別途適合性を確認します |

この表の「推奨する対応層」は新たに提示する対応表案です。実際に対応を宣言する際は、層ごとの構文適合試験を通過していることを条件とします。

### 2.2 プロファイル

プロファイルは、言語仕様の構文・意味のうち、実装や用途に応じて受理する部分集合です。同じプロファイルで受理されたプログラムの意味を、プロファイル選択によって変えてはいけません。プロファイルで許可されていない構文は、推測して受理せず、診断してください。従来経路との互換動作が異なる場合は、互換機能として別に記録してください。

**確定（Lv1.4方針）:** MVPは「層0の共通意味を中心に、静的クラスOOPターゲットへ写像する限定プロファイル」として位置付けます。`Program` クラスと `Main(string[] args)` はクラスなしの中核の規則ではなく、層0の関数を静的クラスOOPターゲットの実行単位へ写像するMVPプロファイル規則です。`--mvp` は、この受理範囲を選択する処理系オプションです。

MVPで確定した規則のうち、整数・文字列・真偽値、演算子、短絡評価、戻り値、条件分岐、前判定の繰り返しなどは、層0の言語全体規則として採用します。入口、`Program`、`static`、MVPの許可構文一覧、MVPでの識別子制約など、クラスや実装範囲に依存するものはMVPプロファイルの制限とします。

## 3. 字句規則

### 3.1 文字・空白・行

- **確定（MVP）:** 入力は厳密なUTF-8として読みます。不正なUTF-8はエラーとし、置換文字へ黙って置き換えません。UTF-8 BOMはファイル先頭にある場合だけ除去できます。
- **確定（Lv1.4方針）:** 改行にはLFまたはCRLFを使用できます。行番号は1始まりです。タブ、半角空白、全角空白はトークン区切りとして扱い、字句上の意味を変えません。行頭インデントはブロック構造を定めません。
- **確定（Lv1.4方針）:** 物理改行は単純文の終端です。括弧内や文字列リテラル中の改行は許可しません。ブロック境界は改行やインデントではなく、構文記号で表します。

**確定記号と文字コード**

| 記号 | Unicodeコードポイント | 用途 |
|---|---|---|
| `▽` | U+25BD | 宣言・ブロック開始 |
| `△` | U+25B3 | 関数・クラスの終端 |
| `▼` | U+25BC | Alias宣言 |
| `▲` | U+25B2 | Aliasの終端 |
| `□` | U+25A1 | 実行文 |
| `■` | U+25A0 | Import宣言 |
| `◇` | U+25C7 | 分岐・例外処理 |
| `〇` | U+3007 | 繰り返し |
| `・` | U+30FB | 変数・定数宣言 |

類似文字（例：`○` U+25CB）は代替記号として扱いません。

**確定（Lv1.4方針）：識別子**

- 識別子の先頭にはUnicode文字または `_` を使用できます。2文字目以降にはUnicode文字、Unicode数字、`_` を使用できます。
- 識別子の比較は、Unicode正規化や大文字・小文字変換をせず、入力されたコードポイント列で行います。
- ターゲット間の意味を揃えるため、いずれかの出力先で予約語となる名前は、全ターゲット共通で使用できません。暗黙の改名をせず診断します。
- VB.NETの大文字・小文字を区別しない名前解決との衝突を防ぐため、同一スコープ内に大文字・小文字だけが異なる名前を宣言できません。
- キーワードと隣接識別子はトークン境界で区別します。空白なしの連結を特別に許可する構文は、個別に列挙したものに限ります。

### 3.2 コメント

- **確定（MVP）:** `//` は行末まで、`/* ... */` は閉じ記号までのコメントです。字句解析時に無視します。閉じていないブロックコメントは位置付きエラーです。コメントの生成ソースへの保持はMVP保証外です。
- **確定（Lv1.4方針）:** ブロックコメントの入れ子は認めません。`/** ... */` は将来の名前対応コメントとして通常コメントと区別しますが、MVPプロファイルでは識別子の改名に使用しません。

## 4. 型・宣言・名前解決

### 4.1 基本型

次の3型は**確定（MVP）**であり、MVPにおけるあおいの正規型名です。あおいソースにはターゲット物理型名ではなく、あおいの論理型名を書きます。

| あおい型 | C# | Java | VB.NET |
|---|---|---|---|
| `int` | `int` | `int` | `Integer` |
| `string` | `string` | `String` | `String` |
| `bool` | `bool` | `boolean` | `Boolean` |

**対応表案：基本型と今後の追加候補**

| あおい論理型名 | C# | Java | VB.NET | 状態 |
|---|---|---|---|---|
| `long` | `long` | `long` | `Long` | 追加時の候補です |
| `double` | `double` | `double` | `Double` | 追加時の候補です |
| `decimal` | `decimal` | `BigDecimal` | `Decimal` | Java側は演算変換を含めて定義が必要です |
| `char` | `char` | `char` | `Char` | Unicode文字幅・比較規則の定義が必要です |

この表の追加候補はMVPに含まれず、言語全体で受理する型としては未確定です。対応型と演算・比較の意味を一組として定義し、3ターゲット共通で表現できることを確認してから追加します。

**対応表案：配列型**

| あおい論理型 | C# | Java | VB.NET |
|---|---|---|---|
| `int[]` | `int[]` | `int[]` | `Integer()` |
| `string[]` | `string[]` | `String[]` | `String()` |
| `bool[]` | `bool[]` | `boolean[]` | `Boolean()` |

あおいの配列型記法は `要素型[]` とします。上表は基本型の1次元配列に限る対応表案です。

### 4.2 変数・定数の宣言

宣言は `・` で始め、代入などの実行文は `□` で始めます。`定数` は定数宣言を示します。

```aoi
・int 年齢 = 34
・string 名前 = "花子"
・bool 特待区分 = true
・定数int 上限 = 10
```

**確定（MVP）:** MVPではint/string/boolのローカル変数・定数を受理します。初期値は必須です。変数は同一スコープ内で重複宣言できず、定数は再代入できません。MVPの定数初期値は基本リテラルに限ります。変数は宣言位置以降の同一ブロックで有効です。

**確定（Lv1.4方針）:** 言語全体でも、変数・定数は宣言位置以降の同一ブロックで有効とします。同一スコープの重複宣言はエラーです。定数の初期化要否と、許される初期値の範囲はプロファイルごとに明記します。

変数を宣言した後に値を代入する場合は、実行文の先頭に `□` を付けます。宣言と初期化を一つの文にまとめることもできます。

```aoi
・int 税込価格
□税込価格 = 消費税を計算する(価格, 軽減税率適用可否)

・int 計算済み価格 = 消費税を計算する(価格, 軽減税率適用可否)
```

この例の関数は、同じスコープから呼び出せる関数として宣言されているものとします。MVPプロファイルでは、初期値のない変数宣言は受理しません。

### 4.3 配列

配列は**対象外（MVP）**です。MVPの入口引数 `string[] args` はターゲット起動規約のための特例であり、一般配列を宣言・操作できることを意味しません。

**確定（Lv1.4方針）：** 配列型は `要素型[]` と記述し、ターゲット構文を直接書きません。配列初期化は角括弧で囲みます（例：`[1, 2, 3]`）。要素アクセスは `配列式[添字式]` とします。Lv1.4では1次元配列だけを共通仕様とします。空配列は `[]`、多次元配列および配列リテラルの入れ子は対象外です。

**確定（Lv1.4方針）：** 定数配列は参照の再代入と要素の変更の両方を禁止します。意味解析で変更を拒否し、各ターゲットでは読み取り専用の表現を使用します。ターゲットが指定の不変性を保証できない場合は、そのターゲット向け変換をエラーにします。

**配列の宣言と要素の読み書き**

```aoi
・int[] 得点一覧 = [80, 95, 72]
・string[] 名前一覧 = ["花子", "太郎", "芽衣"]
・bool[] 合格一覧 = [true, false, true]

・int 最初の得点 = 得点一覧[0]
□得点一覧[1] = 100
```

添字は0から始まる整数式です。添字が配列の範囲外になった場合の実行時結果は、ターゲットごとの動作差があるため、共通の結果を保証しません。添字の有効範囲を静的に判定できる場合は、範囲外アクセスを診断します。

**定数配列の宣言**

```aoi
・定数int[] 固定得点 = [10, 20, 30]
・int 一件目 = 固定得点[0]
```

次の操作は、定数配列の要素を書き換えるためエラーです。

```aoi
□固定得点[0] = 99
```

定数配列の初期化式は、配列要素の型に一致するリテラルの並びに限ります。空配列は `[]` で表します。多次元配列と配列リテラルの入れ子は受理しません。

### 4.4 名前対応コメント

**対象外（MVP）:** MVPではJavadoc風コメントによる名前変更を行いません。識別子はそのまま出力し、いずれかのMVPターゲットで無効な名前や予約語は診断します。

**確定（Lv1.4方針）：** 拡張プロファイルで名前対応コメントを使用する場合、宣言直前の要約行をクラス・関数・変数のターゲット名に使用します。`@param 日本語名 英字名` は引数名の対応に使用します。`@return` は名前解決に使用せず、文書化用途に限ります。英字名は全ターゲットで共通とし、予約語・無効名を暗黙に正規化せず診断します。

**対応表案：名前コメントの有効範囲**

| コメント対象 | 対応先 | 重複・無効時 |
|---|---|---|
| 宣言直前の要約行 | クラス、関数、変数の出力名 | 重複指定・無効名をエラーにします |
| `@param 日本語名 英字名` | 指定された引数の出力名 | 引数名が存在しない場合はエラーにします |
| `@return` | 文書コメントのみ | 名前や戻り値型の解決には使いません |

コメントの行形式は標準Javadocの要約行とタグ行を用います。複数行コメントの先頭にある空白と `*` は除去してから解釈します。

**名前対応コメントの例**

```aoi
/** nenrei */
・int 年齢 = 34

/**
 * nenreiwoKasanSuru
 * 年齢を加算します。
 * @param 加算量 amount
 * @return 加算後の年齢です。
 */
▽int 年齢を加算する(int 加算量)
    □年齢 + 加算量 を 返す
△
```

この例では、`年齢` のターゲット名は `nenrei`、関数のターゲット名は `nenreiwoKasanSuru`、引数のターゲット名は `amount` です。`@return` は説明文であり、名前や型の解決には使いません。この機能はMVPプロファイルでは使用しません。

## 5. 式と演算子

### 5.1 MVPで確定した式の意味

| 分類 | あおい記法・意味 | C#・Java・VB.NETへの対応 |
|---|---|---|
| 整数 | `int` は符号付き32ビット整数です | C# `int`、Java `int`、VB.NET `Integer` へ変換します |
| 整数算術 | `+ - * / %` を使用します。共通の優先順位と括弧を適用します | VB.NETでは `%` を `Mod` へ変換します |
| 除算 | int同士の整数除算です。小数部はゼロ方向へ切り捨てます | オーバーフローしない入力で結果を一致させます |
| 数値比較 | `< > <= >= == !=` を使用します | 共通のbool結果へ変換します |
| 基本型の等価比較 | 同じ基本型の値について `== !=` を使用します | stringは序数による値比較へ変換します |
| 文字列大小比較 | MVPでは禁止します | 意味解析で診断します |
| 論理演算 | boolの `! && ||` を使用します。`&&` と `||` は短絡評価です | VB.NETでは `Not`、`AndAlso`、`OrElse` へ変換します |
| 型変換 | 暗黙の数値変換を行いません | 型不一致を生成前に診断します |
| 文字列エスケープ | `\\`、`\"`、`\n`、`\r`、`\t` を受理します | 3ターゲットで同じ文字列値になるよう出力します |

整数オーバーフローの結果はMVP保証外であり、3ターゲット間で同一とは限りません。ゼロ除算はコンパイル可能な実行時エラーとして扱います。終了コードや例外形式のターゲット差は受入比較の対象外です。

**確定（Lv1.4方針）:** 上記の演算子・型規則を層0の言語全体規則とします。型・演算子の決定は意味解析で完了させ、生成器の型推論に意味を委ねません。

**対応表案：文字列等価比較**

| あおい式 | C# | Java | VB.NET |
|---|---|---|---|
| `left == right` | `String.Equals(left, right, StringComparison.Ordinal)` | `left.equals(right)` | `String.CompareOrdinal(left, right) = 0` |
| `left != right` | `!String.Equals(left, right, StringComparison.Ordinal)` | `!left.equals(right)` | `String.CompareOrdinal(left, right) <> 0` |

生成側はnull非許容のMVP文字列を前提とします。nullable文字列を導入する場合は、別途null比較規則を定めます。

**式と演算子の例**

```aoi
・int 合計 = 6 + 2 * 3
・int 商 = 7 / 2
・int 余り = 7 % 2
・bool 条件成立 = 合計 >= 10 && 余り == 1
・bool 条件不成立 = !(合計 == 12) || 商 < 0
・bool 文字列一致 = "あおい" == "あおい"
```

この例では、乗算を加算より先に評価し、括弧がある場合は括弧内を先に評価します。`&&` は左辺が偽なら右辺を評価せず、`||` は左辺が真なら右辺を評価しません。文字列の大小比較（`<`、`>` 等）はできません。

### 5.2 未確定の型・式

MVPに含まれない小数、文字、十進数、文字列連結、暗黙の文字列化、nullリテラル、nullable型、派生型代入互換、オーバーフロー時の動作は、対応表案と適合試験が整うまでMVPの範囲外です。

各型について、3ターゲットの表現、リテラル、演算、比較、変換規則を一組として定義します。規則のない暗黙変換は認めず、ターゲット言語ごとに挙動が変わる式は受理しません。

### 5.3 null条件・null合体演算子

`?.` と `??` は**対象外（MVP）**です。将来サポートする場合は、式の再評価が安全と確認できるものだけを展開し、それ以外は診断します。

**確定（Lv1.4方針）：** 安全なreceiverは、ローカル変数・引数など評価に副作用がない単純識別子に限ります。関数呼出し、プロパティ参照、添字式、代入式は安全な式に含めません。nullable型と式の結果型の規則が決まるまでは、これらの演算子を共通プロファイルに含めません。

## 6. 関数と実行文

### 6.1 関数の宣言と呼び出し

関数宣言は `▽` で始まり、`△` で終わります。引数と戻り値にはあおい型名を用います。呼出しは位置引数とし、引数の型・個数を意味解析で検査します。

戻り値のない関数は、戻り値型を省略して宣言できます。省略した場合は `void` と同じ意味です。`void` を明記する形も引き続き受理し、どちらの形でも値を返すことはできません。戻り値のある関数では戻り値型を省略できません。

```aoi
▽int 合計する(int 左の値, int 右の値)
    □左の値 + 右の値 を 返す
△

▽得点を表示する(int 得点)
    □コンソール.一行表示する(得点)
△
```

**確定（MVP）:** 引数なし・1引数・複数引数を許可します。関数の引数と戻り値の組合せを関数本体の解析前に登録するため、関数呼び出しは宣言順に依存しません。未定義関数、引数の個数・型不一致は診断します。MVPではオーバーロード、参照渡し、既定値引数、可変長引数、一般クラスメソッドを受理しません。

**確定（Lv1.4方針）:** 引数には通常の式を指定できます。関数呼び出しを含む式も引数に使えます。日本語の助詞「で」「を」を使う呼び出しは、構文規則に列挙した形だけを対応するプロファイルで受理し、意味解析では助詞を取り除いて同じ呼び出しとして扱います。関数名はプロファイル内で一意とし、再帰は許可します。オーバーロードは導入しません。参照渡し・既定値引数・可変長引数も共通プロファイルでは許可しません。

**戻り値のない関数の呼び出し例**

```aoi
・int 合計 = 合計する(3, 5)
・int 二倍した合計 = 合計する(合計, 合計)
□得点を表示する(二倍した合計)
```

従来例にある次の形も、同じ関数を呼び出す構文のひとつとして示します。この形はMVPでは対応していません。MVP以外でも、対応する構文規則を実装したプロファイルでのみ使用できます。

```aoi
□(二倍した合計)で 得点を表示する
```

引数はカンマで区切り、宣言された順に渡します。引数を受け取らない関数は `()` を空にします。関数呼び出し式は、変数の初期値、代入式、他の関数の引数に指定できます。関数名は一意であるため、引数の型だけで同名関数を選ぶオーバーロードはありません。

### 6.2 値を返す処理

**確定（MVP）:** 正規形は `□値を 返す` です。互換形 `□値 を 返す` および `□return 値` も同じ意味として受理します。それ以外の形は受理しません。値を返す関数は、すべての実行経路で型の一致する値を返す必要があります。すべての経路で値を返すことを意味解析で検査します。

```aoi
▽int 値を返す(int 入力値)
    □入力値 を 返す
△
```

**確定（Lv1.4方針）:** 正規形を言語全体で採用し、MVPで定めた2つの互換形もLv1.4では同じ意味の互換構文として維持します。`@return` は実行上の名前解決に影響させず、文書化用途に限ります。

### 6.3 実行文の接頭記号

`□` は代入、関数呼び出し、値を返す文など、実行文の開始記号です。宣言は `・` で始めます。MVPで許可する実行文は、代入、関数呼び出し、値を返す文に限ります。

**確定（Lv1.4方針）:** `□` は仕様に列挙された実行文だけに使用します。一般式文や未定義の式を `□` の後に書くことはできません。クラスメンバーアクセス等の複合左辺は、該当プロファイルの意味が定義されている場合に限り許可します。

## 7. ブロック・分岐・繰り返し

### 7.1 ブロック終端

終端省略は、明示的に許可された構文・位置だけに認めます。MVPの終端省略許可一覧は**空集合**です。

| ブロック | MVPの明示終端 |
|---|---|
| 関数・クラス | `△` |
| 条件分岐 | `◇ここまで` |
| 前判定の繰り返し | `〇ここまで` |

**確定（Lv1.4方針）:** 言語全体の終端省略許可一覧も初期値を空集合とします。単独の `◇`・`〇` は終端記号として認めません。`ここまで` を含む明示形を使用します。ブロックスタックで開始・中間節・終端の対応を検査し、重複・異種・不足終端や曖昧な省略は位置付きエラーにします。

### 7.2 条件分岐

```aoi
◇点数 > 0 の場合
    □コンソール.一行表示する(点数)
◇他に
    □コンソール.一行表示する("点数がありません")
◇ここまで
```

**確定（MVP）:** `◇条件 の場合`、任意の `◇他に`、明示終端を許可します。条件分岐の入れ子を許可します。`◇他に 条件の場合` の形式はMVPでは受理しません。条件はbool型です。

**確定（Lv1.4方針）:** 1行条件文は受理しません。分岐には必ずブロック終端を付けます。条件付きの「他の場合」を将来追加する場合は、親となる条件分岐の中間節としてブロックスタック上の対応を定義します。

**条件を追加した分岐の例**

MVPではelse-ifを受理しないため、条件が複数ある場合は条件分岐を入れ子にします。

```aoi
◇点数 >= 80 の場合
    □コンソール.一行表示する("優")
◇他に
    ◇点数 >= 60 の場合
        □コンソール.一行表示する("良")
    ◇他に
        □コンソール.一行表示する("再確認")
    ◇ここまで
◇ここまで
```

**入れ子の条件分岐の例**

```aoi
◇点数 >= 0 の場合
    ◇点数 >= 合格点 の場合
        □コンソール.一行表示する("合格")
    ◇他に
        □コンソール.一行表示する("不合格")
    ◇ここまで
◇他に
    □コンソール.一行表示する("点数が不正です")
◇ここまで
```

### 7.3 前判定の繰り返しと繰り返し制御

```aoi
〇count < limit の間は繰り返す
    □count = count + 1
〇ここまで
```

**確定（MVP）:** 前判定の繰り返しを許可します。条件は各反復の前に評価し、bool型を要求します。0回および複数回の反復が可能です。

カウンタ式の繰り返し、無限繰り返しの省略形、後判定の繰り返し、`□脱出する`、`□ループ先頭へ` は**対象外（MVP）**です。

**確定（Lv1.4方針）：** 将来のループ制御文は `□脱出する` と `□ループ先頭へ` に統一します。「やめる」は廃止します。`□脱出する` は、現在位置を含む最も内側のループまたはswitchを1つだけ終了します。ループ内のswitchで使った場合はswitchだけを終了し、外側のループは終了しません。`□ループ先頭へ` は、最も内側のループの次の反復へ移動します。

**後判定の繰り返し**

後判定の繰り返しは、本体を一度実行してから条件を評価します。開始記号は `〇ここから`、最終行は条件を含む `〇条件 の間は繰り返す` とします。最終行がブロック終端を兼ねるため、別の `〇ここまで` は付けません。

```aoi
・int 回数 = 0
〇ここから
    □回数 = 回数 + 1
    □コンソール.一行表示する(回数)
〇回数 < 3 の間は繰り返す
```

この例では、本体を3回実行します。後判定の繰り返しはMVP対象外です。

**次の反復へ進む例**

```aoi
・int 回数 = 0
〇回数 < 5 の間は繰り返す
    □回数 = 回数 + 1
    ◇回数 == 2 の場合
        □ループ先頭へ
    ◇ここまで
    □コンソール.一行表示する(回数)
〇ここまで
```

`回数` を条件判定の前に更新しているため、次の反復へ進んでも停止条件に到達できます。

**ループを抜ける例**

```aoi
・int 回数 = 0
〇回数 < 10 の間は繰り返す
    □回数 = 回数 + 1
    ◇回数 == 4 の場合
        □脱出する
    ◇ここまで
    □コンソール.一行表示する(回数)
〇ここまで
```

この例では、`□脱出する` がその位置を含む最も内側のループだけを終了します。これらのループ制御文はMVPでは受理しません。

### 7.4 値による多分岐（場合分け）

値による多分岐は**対象外（MVP）**です。既存の `-b` フォールスルー設定は処理系の互換機能であり、多分岐の言語全体の意味を確定するものではありません。

**確定（Lv1.4方針）：** 値による多分岐の既定動作はフォールスルーなしです。case値の文法と重複値は意味解析で検査します。`-b e` と `-b n` は選択した動作をすべてのターゲットで同じ意味になるよう適用します。`-b t` はターゲット依存の互換動作であり、ターゲット中立性を要求するプロファイルではエラーにします。`□脱出する` は多分岐の中では多分岐だけを終了します。ループ内の多分岐からループまで抜ける場合は、多分岐を終了した後にループ制御文を実行してください。

```aoi
◇番号 で分岐する
◇1
    □コンソール.一行表示する("一番")
◇2
    □コンソール.一行表示する("二番")
◇既定
    □コンソール.一行表示する("その他")
◇ここまで
```

この例では、各分岐の処理後に次のcaseへ進みません。`□脱出する` は省略できます。case値は定数式とし、同じ値を複数のcaseに指定することはできません。値による多分岐はMVP対象外です。

## 8. クラスとオブジェクト

一般的なクラス・インスタンス・継承機能は**対象外（MVP）**です。MVPの `Program` は生成単位と実行入口を収める構造上のラッパーに限ります。

### 8.1 層1・層2の記法

**確定（Lv1.4方針）：** クラス宣言も `▽` で開始し、クラス名、基底型、メンバーをあおい正規記法で表します。継承の正規記号は `:` とし、Java `extends`、VB.NET `Inherits` 等のターゲット構文へ生成器が変換します。継承なしのクラスを層1、継承を含むクラスを層2とします。

クラス宣言は `▽クラス クラス名`、継承を行う場合は `▽クラス クラス名 : 基底クラス名` と記述します。メンバー宣言では、アクセス範囲の後に `static` または `instance` を指定できます。どちらも指定しない場合は `instance` として扱います。両方を指定する宣言は認めません。

```aoi
▽クラス 人物
    ・private instance int 年齢 = 0

    ▽public instance int 年齢を取得する()
        □年齢 を 返す
    △
△

▽クラス 会社員 : 人物
    ・private instance int 社員番号 = 0

    ▽public instance int 社員番号を取得する()
        □社員番号 を 返す
    △
△
```

クラス、メンバー、関数の終端には `△` を付けます。上の例では、`会社員` が `人物` を継承しています。基底クラスの初期化順、継承メンバー探索、override、interface実装は、対応するターゲット間で意味が一致するよう定義します。

### 8.2 static、アクセス、インスタンス

**確定（Lv1.4方針）：** `static` を指定したメンバーは型に属し、`instance` を指定したメンバーと修飾子を省略したメンバーはインスタンスに属します。省略時の扱いはターゲットごとに推測せず、言語規則として `instance` に固定します。VB.NETの `Shared` 自動昇格を言語意味にしません。

**対応表案：修飾子**

| あおい修飾子 | 意味 | C# | Java | VB.NET |
|---|---|---|---|---|
| `public` | すべての利用側からアクセスできます | `public` | `public` | `Public` |
| `protected` | クラスおよび派生クラスからアクセスできます | `protected` | `protected` | `Protected` |
| `private` | 宣言したクラス内だけでアクセスできます | `private` | `private` | `Private` |
| `static` | 型に属するメンバーです | `static` | `static` | `Shared` |
| `instance` | インスタンスに属するメンバーです | 修飾子なし | 修飾子なし | `Shared` なし |
| `internal` | 共通プロファイルでは使用しません | `internal` | package-private | `Friend` |

`internal` 相当の可視性はターゲットごとに境界（アセンブリ、パッケージ等）が異なるため、共通プロファイルでは受理しません。Alias内のターゲット固有宣言では、ターゲット別に使用できます。

**対応表案：コンストラクタ**

| あおい記法案 | C# | Java | VB.NET |
|---|---|---|---|
| `▽コンストラクタ(引数...)` | クラス名のコンストラクタ | クラス名のコンストラクタ | `Sub New(引数...)` |

コンストラクタは戻り値型を持ちません。基底コンストラクタ呼出しと初期化順はターゲット間で同じ意味にできる範囲に限り、表現できない場合は診断します。

**コンストラクタとインスタンス生成**

```aoi
▽クラス 会員
    ・private instance int 会員番号 = 0

    ▽public コンストラクタ(int 番号)
        □会員番号 = 番号
    △

    ▽public instance int 番号を取得する()
        □会員番号 を 返す
    △
△

▽void 会員を確認する()
    ・会員 一人目 = new(101)
    ・int 番号 = 一人目.番号を取得する()
    □コンソール.一行表示する(番号)
△
```

インスタンス生成は `・クラス名 変数名 = new()` を基本形とし、引数がある場合は `new(引数...)` とします。`new()` の対象型は左辺の宣言型から解決します。型が一意に決まらない場合はエラーです。上の例は一般クラスを使うため、MVPプロファイルでは受理しません。

### 8.3 入口関数のターゲット対応

MVPの `Program` と `Main(string[] args)` は、MVPプロファイルの起動規則です。`args` は起動規約のための配列であり、一般配列機能を意味しません。

**対応表案：MVP入口**

| ターゲット | 生成する入口 |
|---|---|
| C# | `Program` の `public static void Main(string[] args)` |
| Java | `Program` の `public static void main(String[] args)` |
| VB.NET | `Program` 内の `Public Shared Sub Main(args As String())` |

## 9. 例外処理

例外処理は**対象外（MVP）**です。MVPで受入したゼロ除算等の実行時失敗のターゲット別終了状態は、言語仕様上の例外処理機能の受入とは別です。

**確定（Lv1.4方針）：** 例外処理は `◇試す`、`◇捉まえる(型 変数)`、任意の `◇必ず最後に`、`□投げる 式` を使用します。例外型と生成式はあおい論理型・式で定義し、ターゲット構文を直接埋め込みません。try/catchを実現できないターゲットへの変換は、明示的なエラーにします。

**対応表案：基本例外型**

| あおい論理型 | C# | Java | VB.NET |
|---|---|---|---|
| `例外型` | `System.Exception` | `RuntimeException` | `System.Exception` |

Javaではチェック例外による追加の宣言を要求しないよう、基本例外型を `RuntimeException` に対応付けます。Importで使用する別のJavaチェック例外はターゲット依存のAlias内に限定し、共通の関数シグネチャへ漏らしません。派生例外型は、3ターゲットに共通対応があるものだけ論理型として追加します。

catch型の適合性、catch節の順序、catch変数のスコープ、finallyからの制御移動は、上記の意味を基準に診断規則を設けます。ターゲットで同じ意味を表現できない場合は変換を拒否します。

**例外を発生させる例**

```aoi
▽void 状態を通知する()
    ・例外型 エラー = new()
    □投げる エラー
△
```

この例では、`例外型` の既定コンストラクタで例外を生成します。ターゲットごとの `throw`、`Throw`、`throws` の記述はソースへ書かず、生成器が対応付けます。

**例外を捕捉し、最後に処理する例**

```aoi
▽void 入力を処理する()
    ◇試す
        □入力を検証する()
    ◇捉まえる(例外型 エラー)
        □コンソール.一行表示する("処理できませんでした")
    ◇必ず最後に
        □後片付けする()
    ◇ここまで
△
```

`入力を検証する` と `後片付けする` は、同じプログラム内に宣言された値を返さない関数です。複数の捕捉節を記述する場合は、派生例外型を先に、基底例外型を後に置きます。同じ型または到達不能な捕捉節はエラーです。

## 10. 組込み関数・Import・Alias

### 10.1 中立な組込み機能

**確定（MVP）:** `コンソール.一行表示する(式)` はターゲット中立な組込み関数です。引数はstringまたはintに限り、boolは拒否します。一般Aliasを使わず、各ターゲットの標準出力APIへ対応付けます。

**対応表案：コンソール出力**

| あおい呼出し | 引数型 | C# | Java | VB.NET |
|---|---|---|---|---|
| `コンソール.一行表示する(式)` | `string` | `Console.WriteLine(式)` | `System.out.println(式)` | `Console.WriteLine(式)` |
| `コンソール.一行表示する(式)` | `int` | `Console.WriteLine(式)` | `System.out.println(式)` | `Console.WriteLine(式)` |

組込み名は予約名とし、同名の利用者定義関数・Aliasがある場合はエラーにします。よく使う機能は組込み関数として提供し、Import/Aliasを使わず中立性を保ちます。

### 10.2 Import/Alias

Import/Aliasは**対象外（MVP）**です。Importの正規記号は `■インポートする` とし、`■using ...` のようなターゲット構文を一般文法として混在させません。

**確定（Lv1.4方針）：ターゲット依存をAlias定義内に閉じ込めます。**

1. Importの対象名、Aliasのターゲット型名・メンバー名は、ターゲット別に記述します。
2. Alias定義内のターゲット依存を、あおいソース本体の呼出しや型記述へ漏らしません。本体ではAliasに付けたあおい名だけを使用します。
3. ターゲット別のAlias定義は同一の論理APIとして対応付けます。対象ターゲットの定義がない場合は変換時エラーです。
4. Import宣言は対象ターゲットを識別できる形式にします。別ターゲット向けImportを誤って使った場合は明示的に診断します。
5. 同一ターゲットImportの重複、同名Alias、Aliasと完全修飾名の衝突、複数Importによる同名提供はエラーとし、宣言順に依存させません。
6. Aliasメンバーは型・引数・戻り値・static/instanceを明記します。オーバーロードは引数型で一意に解決できる場合に限り許可します。意味解析時に一度だけ名前解決します。

**対応表案：Import/Aliasのファイル分割**

| ファイル名の例 | Import宣言の例 | 用途 |
|---|---|---|
| `console.cs.aoi` | `■インポートする C# System` | C#向けAlias定義 |
| `console.java.aoi` | `■インポートする Java java.lang` | Java向けAlias定義 |
| `console.vb.aoi` | `■インポートする VB.NET System` | VB.NET向けAlias定義 |

各ファイルでは同じあおいAlias名と論理シグネチャを宣言し、ターゲットAPI名だけを対象言語に合わせます。アプリケーション本体は対応するAlias定義群を処理系へ渡して変換します。

この方式では「同じAlias入力がすべてのターゲットで同じ意味」という条件を、各ターゲット向けAlias定義が同じ論理APIを実現することとして扱います。Alias定義がターゲットごとに異なることを受入条件に明記します。

**ターゲット別の別名定義例**

C#向けの別名定義ファイル例です。

```aoi
■インポートする C# System
▼public static class コンソール Console
    ▼public static void 一行表示する(string 値)
        WriteLine(value)
    ▲
▲
```

Java向けでは、同じ論理名と引数型を保ち、ターゲットAPIの名前だけを変えます。

```aoi
■インポートする Java java.lang
▼public static class コンソール System.out
    ▼public static void 一行表示する(String 値)
        println(value)
    ▲
▲
```

VB.NET向けでも同様に定義します。

```aoi
■インポートする VB.NET System
▼Public Shared Class コンソール Console
    ▼Public Shared Sub 一行表示する(String 値)
        WriteLine(value)
    ▲
▲
```

アプリケーション本体はターゲット別のクラス名やメソッド名を書かず、論理名だけを呼び出します。

```aoi
▽void あいさつする()
    ・string 名前 = "花子"
    □コンソール.一行表示する(名前)
△
```

これらは、Importの依存を別名定義に閉じ込める方針を説明する例です。実際に許可するターゲット宣言の細かな文法は、別名宣言の文法表に従います。組込みの `コンソール.一行表示する` を使う場合は、別名定義もImportも必要ありません。

### 10.3 コメント

行コメントは `//` から行末までです。複数行にわたる説明には `/* ... */` を使います。ブロックコメントを入れ子にはできません。

```aoi
// 1行のコメントです。
・int 件数 = 3

/*
  この範囲はコメントです。
  コメント内の宣言や実行文は処理されません。
*/
□コンソール.一行表示する(件数)
```

閉じていない `/*` はエラーです。MVPでは通常コメントを生成先へ残す必要はありません。名前対応コメントは「4.4 名前対応コメント」の規則に従います。

## 11. CLI・生成・診断契約（MVP）

CLIの詳細は処理系契約です。以下はMVPで受入済みの契約を明記したものです。

### 11.1 呼出しとターゲット選択

```text
aoi [--mvp] sourceFile targetFile [-b e|n|t]
```

- 入力拡張子は `.aoi` または `.remind` です。入力文字コードは厳密なUTF-8です。
- 出力拡張子 `.cs_` はC#、`.java_` はJava、`.vb` はVB.NETを選択します。`.cs_`・`.java_` は、トランスパイラ自身のプロジェクトに生成ソースを誤って取り込まないための中間拡張子です。
- 出力先ディレクトリは必要に応じて作成します。入力と出力に同一パスは指定できません。
- `--mvp` と `-b` は独立した設定として併用できます。`-b` の値は `e`（フォールスルー有）、`n`（無）、`t`（ターゲット準拠）です。未指定時は `t` です。結合形・分離形を受け付けます。複数指定または競合はエラーです。
- 未対応のオプション、引数不足・過剰、入力・出力拡張子の不備は失敗です。

### 11.2 失敗・出力

- 失敗時は標準エラーへ診断を出し、非0で終了します。
- 解析・意味解析・生成に失敗した場合、出力ファイルを新規作成せず、既存出力も変更しません。
- 成功時はUTF-8 BOMなしで出力します。同じ入力・設定から再生成した場合、出力はバイト単位で一致します。
- MVPプロファイルの適合試験では、コンパイル・実行後の標準出力を比較します。改行コードと行末空白は比較前に正規化します。不正UTF-8は受入前に失敗とします。
- 実行時例外の終了コード、診断文、例外形式など、ターゲット固有の結果は同一性要件に含めず、ターゲット別に記録します。
- 診断には可能な場合にソース位置を含めます。MVPでは行番号付き診断を受入済みです。列番号の数え方、複数エラーを継続報告する条件、警告とエラーの区別は下記の対応表案に従います。

**対応表案：診断位置・重大度**

| 項目 | 推奨する規則 |
|---|---|
| 行番号 | 1始まりです |
| 列番号 | 1始まりのUnicodeコードポイント数です。タブは1文字として数えます |
| エラー | 解析・意味解析・生成を継続できず、非0終了とします |
| 警告 | 生成を継続できる問題として標準エラーへ出力します。警告だけでは終了コードを非0にしません |
| 複数診断 | 安全に継続できる場合は複数を報告します。構文木の同期が失敗した場合は最初の回復不能エラーで終了します |

### 11.3 ターゲット拡張

C#・Java・VB.NET以外へのMVP変換は実装対象外です。拡張子を認識できない場合、またはターゲット実装が存在しない場合は、未対応ターゲットであることを示して診断します。

## 12. MVPプロファイルの確定範囲

MVP詳細要件v4および完了レポートにより、MVPプロファイルの18要件はC#・Java・VB.NETで受入完了しています。次の表はMVPで確定した受理範囲の要約です。一般言語機能としての範囲を自動的に確定するものではありません。

| 要件 | MVPの受理範囲 |
|---|---|
| 宣言・型 | 初期値付きローカル変数、基本リテラルで初期化するローカル定数、`int`・`string`・`bool` |
| コメント・リテラル | `//`、`/* ... */`、閉じ忘れ拒否、十進整数、二重引用符文字列、true/falseと5種の指定エスケープ |
| 式 | 整数算術、比較、論理演算、優先順位、括弧、短絡評価、型一致。文字列大小比較と暗黙数値変換は禁止です |
| 関数 | `Program` 内関数、位置引数、引数なし・複数引数、宣言順に依存しない解決、全経路return |
| 制御 | if/else（else-ifなし）、入れ子if、前判定while。各ブロックの明示終端が必須です |
| 実行文 | `□` で始まる代入、関数呼出し、return |
| 出力 | `コンソール.一行表示する`。引数はstring/intに限ります |
| パイプライン | 厳密UTF-8入力、Lexerから各ターゲット生成までの正式経路、失敗時診断・非0終了・出力保護 |

配列、null、カウンタ式の繰り返し、後判定の繰り返し、多分岐、`□脱出する` と `□ループ先頭へ`、例外、一般クラス・継承、Import/別名定義、参照渡し、既定値引数、オーバーロード、型引数、条件付きの「他の場合」、終端省略、Javadoc風コメントによる名前変更、任意のターゲット構文はMVP対象外です。

### 12.1 MVPの小さな実行例

次の例は、MVPプロファイルで扱う関数、条件分岐、繰り返し、標準出力を一つにまとめたものです。`Program` は生成単位をまとめるためのクラスです。`Main` と `string[] args` は入口関数の対応規則であり、通常の関数や配列宣言の例ではありません。

```aoi
▽public クラス Program
    ▽static int 合計する(int 左の値, int 右の値)
        □左の値 + 右の値 を 返す
    △

    ▽static void Main(string[] args)
        ・定数int 上限 = 3
        ・int 合計 = 合計する(1, 2)
        ・int 回数 = 0

        ◇合計 == 上限 の場合
            □コンソール.一行表示する("計算結果は3です")
        ◇他に
            □コンソール.一行表示する("計算結果が異なります")
        ◇ここまで

        〇回数 < 上限 の間は繰り返す
            □回数 = 回数 + 1
            □コンソール.一行表示する(回数)
        〇ここまで
    △
△
```

この例の出力は、3ターゲットで次のとおりです。

```text
計算結果は3です
1
2
3
```

受入済みの詳細条件と実行サンプルは[最小セットMVPの詳細要件v4.md](./最小セットMVPの詳細要件v4.md)、[最小セットMVPの詳細要件v4完了レポート.md](./最小セットMVPの詳細要件v4完了レポート.md)、および[tests/Test-MvpAcceptance.ps1](../tests/Test-MvpAcceptance.ps1)を参照してください。

## 13. 適合性と実装共通契約

- 言語全体の意味はあおい側で定め、ターゲット生成器は既定の意味を変えないでください。
- 各ターゲットへの出力で意味を保てない構文は、成功形の出力を返さず診断してください。
- 構文層・プロファイル・ターゲットの組み合わせを宣言し、未対応構文を黙って無視しないでください。
- 正常系・異常系を構文単位の適合テストとして固定してください。特に入れ子ブロック、終端の欠落・不一致、型不一致、名前衝突、ターゲット間の意味一致を検査してください。
- MVPの3ターゲット受入では、C#・Java・VB.NETそれぞれでコンパイルと実行を行い、標準出力・診断・終了状態を契約ごとに記録してください。
