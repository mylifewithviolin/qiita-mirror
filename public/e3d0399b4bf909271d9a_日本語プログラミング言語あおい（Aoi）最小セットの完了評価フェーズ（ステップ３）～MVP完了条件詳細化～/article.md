# 本記事のステップ
## 1. 最小セット（MVP）
まずは「1つの小さなプログラムを通せる」レベルに絞る構成。Phase 1～8に分けて実装完了しました。[^1]
**Phase 9: 検証と品質改善**
[こちらの記事](https://qiita.com/mylifewithviolin/items/de68617a710940b0fb23)でPhase 9をいったん完了し、現在はPhase 10:完了条件の評価に進んでいます。
### Phase 10: 完了条件
前回記事では完了条件満たすため自動生成したあおいの検証用ソースコードをつかって検証・改修・再テスト・再評価を行いました。その結果、内部的に整合のとれていない状態とする設計上の課題が抽出されました。

## 本ステップの課題

#### 生成レスポンス３
>最小セットMVPの詳細要件v4.md を作成しました。
>
>v3のMVP照合項目18件をすべて範囲内／範囲外に分類し、範囲内は受理形式・拒否条件・受入条件を表にしました。達成可能性を優先し、MVPは小さなコンソールプログラムに必要な基本機能に絞っています。配列、null演算子、switch、クラス、一般AliasなどはMVP対象外として、後続仕様での扱いも整理しました。

以下にMVP詳細要件v4の一部抜粋を掲載します。

**docs\最小セットMVPの詳細要件v4.md　一部抜粋**
```md
# Re:Mind 最小セットMVPの詳細要件 v4
## 4. MVP要件の範囲一覧

「範囲内」の行は詳細要件・受入条件に従って実装する。「範囲外」の行はMVPの合否に含めず、MVP完了を妨げない。
```
範囲一覧の表はmdソースの状態ですとみづらいのでQiitaでレンダリングします。
#### 4. MVP要件の範囲一覧
| v3照合項目 | MVP範囲 | MVPで扱う内容 |
|---|---|---|
| 変数宣言・代入 | 範囲内 | int/string/boolのローカル変数、初期値、単純な識別子代入 |
| 定数宣言 | 範囲内 | int/string/boolのローカル定数と再代入禁止 |
| 基本型 int/string/bool | 範囲内 | 3基本型と型の一致する式・引数・戻り値 |
| コメント | 範囲内（限定） | `//`、`/* ... */` を字句解析時に無視。閉じていないブロックコメントは拒否 |
| 整数・文字列・真偽リテラル | 範囲内 | int、string、boolの基本リテラル |
| nullリテラル | 範囲外 | nullable型とターゲット間のnull規則は拡張で扱う |
| 四則演算 | 範囲内（限定） | int同士の `+ - * / %` |
| 比較演算 | 範囲内（限定） | intの大小比較、同一基本型の等価・非等価比較 |
| 論理演算 | 範囲内 | boolの `!`、`&&`、`||` |
| `=`による代入 | 範囲内 | 既宣言の可変ローカル変数への単純代入 |
| 関数呼び出し | 範囲内（限定） | ユーザー定義関数と固定のコンソール出力関数。識別子は3ターゲットで有効な名前に限定 |
| 値を返す関数 | 範囲内（限定） | int/string/boolの単一戻り値、全経路の戻り値検査 |
| return / 返す | 範囲内（限定） | 明示的に許可したreturn表記。表記ゆれは固定 |
| if相当の分岐 | 範囲内（限定） | if/else、入れ子if。else-ifはMVPでは除外 |
| while相当の繰り返し | 範囲内 | 条件付きwhileと明示終端 |
| ブロック終了 `ここまで` | 範囲内（限定） | MVPで許可するブロックに対応した明示終端 |
| `□`で始まる実行文 | 範囲内（限定） | 代入、関数呼出し、returnを個別に許可 |

```md
## 8. MVP受入完了条件

次のすべてを満たすまで、MVP受入完了とは判定しない。

1. 本書の範囲内要件すべてが正式なProgramIR経路に接続されている。
2. 各範囲内要件に正常系・該当する異常系の自動テストがある。
3. 代表統合サンプルがC#、Java、VB.NETすべてでコンパイル・実行され、標準出力
　が一致する。
4. 変換・意味解析エラーでは適切な診断、非0終了、生成物の作成・更新抑止を確認する。
5. 同一入力からの3ターゲット生成が再現可能で、差異は明示したターゲット規則に
　限定される。
6. 対象外機能がテストの不成立や未完了判定として混入せず、将来課題として区別
　されている。
7. テスト環境にないコンパイラや実行環境を成功扱いしていない。
```
