# 使用AI
## GitHub Copilot
GitHub CopilotのPro+版。あおいと本件実装と検証の主担当。
## Microsoft Copilot
Windows11アプリケーションのMicrosoft Copilot。GitHub Copilotの使い方スーパバイザとして利用しています。モードは「無料プラン」のsmart。

# 本記事の課題
GitHub Copilot SDKを使ってリモートのAIエージェントと連携したテキストエディタのPoC／概念実証版の実装

ステップ２はテキストエディタ原型にGithub CopilotチャットUIの実装。Github Copilotとの認証・対話成立にはいたらなくても基盤は実装しておく。

GitHub CopilotのチャットゾーンはVSCodeの場合は右側で縦に見ている感じなので、あおい AI コードエディタもそういう感じにしています。

##### 10. 段階別実行プラン
ここもmdのソース出力ですとみにくいのでQiitaでレンダリングします。
| 段階 | 作業 | 完了条件・次へ進む条件 |
|---|---|---|
| Phase 0: 調査・接続検証 | SDK / CLI の版・ライセンス・配置・認証・権限制御・履歴保存を確認。作業ファイルを含まない最小環境で接続、応答、停止、破棄を確認 | 利用者が明示した接続試験で応答を取得し、意図しないツール・ファイル読込が禁止される。制御不能ならここで停止 |
| Phase 1: 文書状態分離 | 単一文書の状態・操作を文書タブとワークスペースへ分割。保存サービスを再利用 | BOM・改行・保存失敗・外部変更等の既存保護を維持。旧試験の仕様変更箇所を明示 |
| Phase 2: 複数文書 UI | タブ、新規・開く・同一パス重複防止・閉じる・全保存・終了確認・Undo 履歴保持 | 複数文書を往復しても内容と履歴を保持。保存失敗で別文書を閉じない |
| Phase 3: 3 ペインと対話 UI | 右ペイン・境界・開閉、履歴・入力・添付一覧・状態表示を実装 | 偽サービスで送信・回答・停止・エラーを操作でき、中央編集が阻害されない |
| Phase 4: Copilot 接続 | 検証済み版を固定、認証状態・モデル・ストリーム・停止・再接続・終了処理を接続 | 実認証で 1 往復、連続対話、停止、再接続を確認。資格情報を記録せず、残存プロセスなし |
| Phase 5: 明示コンテキスト | 選択範囲・現在文書・選択ファイル、プレビュー、版固定、削除、上限と送信確認 | 未保存バッファを正確に送信し、未指定ファイルの読込・送信がないことを検証 |
| Phase 6: 統合・性能・引渡し | 全体終了、エラー、IME・キーボード、複数文書・大量ツリー・受信中の性能、手順と制約を整理 | 自動試験と実接続試験を分けて結果を記録し、未検証事項と再開課題を明示 |
| Phase 7: 任意の追加 | 差分レビュー・利用者承認による編集バッファへの適用 | 初期到達点とは別の承認を受け、版不一致・Undo・保存保護を検証 |

上記はあくまでごく一部の内容です。GitHub Copilotは律儀な技術者かたぎの雰囲気で非常に詳しくこれから実装しようとする内容を説明しています。
