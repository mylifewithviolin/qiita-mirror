## コード生成ルール.md
このmanual-mdフォルダ内の言語マニュアルを必ず読み行くというルールを作成します。

```md:docs\Mind言語のコード生成ルール.md
# Mind言語のコード生成ルール

## 必須参照資料

Mind言語のコードを生成、補完、修正するときは、ワークスペースの `manual-md` フォルダ内にあるすべての `.md` ファイルを参照する。

特定のファイルだけを参照して判断してはならない。構文、予約語、変数、構造体、処理単語、入出力、ファイル操作、GUI、イベント、ウィジェット、属性、レイアウト、ダイアログ、描画、音声、デバッグ、制限事項など、コードに関係する仕様を `manual-md` 全体から確認する。

## 準拠要件

- 構造体の定義は、マニュアルに記載された定義、フィールド、型、値の扱いに完全準拠する。
- 処理単語、予約語、組み込み機能の名称、引数、引数順、戻り値、実行条件は、マニュアルの記述に完全準拠する。
- GUIコードは、GUIライブラリの仕様、ウィジェット、属性、イベント、レイアウト、ウィンドウ、ダイアログ、メニューバー、キャンバスなどの関連記述に完全準拠する。
- マニュアルに記載されていない構文、識別子、API、引数、型、動作を推測で追加しない。
- マニュアル間で記述が異なる場合は、差異を明示し、独断で補完せず確認を求める。
- 仕様を確認できない部分は、推測でコードを完成させず、不明点として示す。
- 生成コードは、マニュアルにあるサンプル、命名、記法、制約に合わせる。

- Mind 言語のソースコードは Shift_JIS（SJIS）で保存する。
UTF-8 で保存するとコンパイラが正しく解析できない。
- SJIS で文字化けしやすい記号（波ダッシュ、全角チルダなど）は使用禁止。
- Copilot は UTF-8 でテキストを生成するため、SJIS に変換しても壊れない文字のみを使用する。


## 生成前の確認

1. `manual-md` 内の全 `.md` を参照する。
2. 使用する構文、処理単語、構造体、GUI要素の仕様を確認する。
3. 引数、型、戻り値、イベント、実行順序、制限事項を確認する。
4. マニュアルにない推測が混入していないことを確認する。

## 仕様が不足している場合

必要な仕様が `manual-md` に見つからない場合は、推測で実装せず、必要な情報を質問する。既存コードに合わせる場合も、マニュアルに反する記法を優先してはならない。

```
このmdはMicrosoft Copilotに作ってもらっていました。一発で上記の状態になったわけではなく、Mind（Windows版）のソースコードはSJISなんですよという情報提供あたりから、こういう制約追加した方がいいですよという流れで下記の制約文を追記しています。ここは重要です。

```md:docs\Mind言語のコード生成ルール.md
- Mind 言語のソースコードは Shift_JIS（SJIS）で保存する。
UTF-8 で保存するとコンパイラが正しく解析できない。
- SJIS で文字化けしやすい記号（波ダッシュ、全角チルダなど）は使用禁止。

```

## tasks.json
VSCodeのタスクにGitHub CopilotがMindコンパイラを自動実行できるように下記のtasks.jsonを設定します。

```json:.vscode\tasks.json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "build",
      "type": "shell",
      "command": "call C:\\Mind9\\usemind.bat && mind ${fileBasenameNoExtension} guilib",
      "group": "build",
      "problemMatcher": []
    }
  ]
}


```
下記はMind9のインストールフォルダ内にある環境設定バッチです。GitHub CopilotがコンソールでmindコンパイラのCLIコマンドラインを実行する都度その直前に実行するようにします。

```cmd
C:\Mind9\usemind.bat
```
