# この小技に関連するMind言語マニュアル

この小技に関連するMind言語仕様の記述はMind8プログラミングマニュアルに記載があります。
９ ファイル操作
└ファイルの読み出し
　└一行読み出し


>　構文＝＜論理ファイル＞から　一行読み出し　→　＜文字列＞
>　　　　　　　　 ↑
>　論理ファイル名の送り仮名は必須で、「から」のほか、「より」、「を」も可
>
>論理ファイルから１行分の文字列を読み出す。

※本記事の主題は「一行読み出し」ではないので、詳しい注意書きは割愛します。全文は[Mindの小技「一行読み出し」](https://qiita.com/mylifewithviolin/items/400bd2153d1b9bf85182)または公式マニュアルをご参照ください。

>構文＝　データ終り？　→　＜真/偽＞
>
>　ファイルからの読み出しで必ず使う処理単語である。
　最後のデータを読み出したあと、なおもデータを読み出した場合に真が返される。真が返された場合には、直前の読み出しは無効なので、データを使用してはならない。
 
本機能（本記事）は、下記のバージョンに対応しています。Mind８のLinux版も対応していると思いますが、本記事では特に検証を行っておりません。

# 小技の解説
Mindの小技「データ終り？」は、MindのファイルのEOF判定機能です。公式マニュアルより詳しい説明が、Mind7の付属の上級者向けドキュメントmind7\doc\file.docmにあります。

>Ｆ５．　ファイルの読み書き
>￣￣￣￣￣￣￣￣￣￣￣￣￣
>■データ終り？
　機能拡張されました。次の二通りの記述が可能です。
　　　　－－－－－－－－－－－－－－－－－－－－－－－－－－－－－－－－
　　　　　　　　　　　　　　データ終り？　→　真／偽
　　　　＜論理ファイル＞が　データ終り？　→　真／偽　　　（←新規機能）
　　　　　　　　　　　　↑送り必須
　　　　－－－－－－－－－－－－－－－－－－－－－－－－－－－－－－－－
のどちらも使用できます。たとえば、二つのファイルを交互に読むようなケースで、それぞれの読み出し操作をした後からでも「データ終り？」を見ることができます。

基本的に論理ファイルを省略した場合は、直前に「一行読み出し」を行った論理ファイルのEOFが判定されますが、安全に判定するには論理ファイルを指定してセットで記述しておくとよいです。

下記のソースはあくまで「データ終り？」のサンプルのため、ローカル変数「ファイル情報」を使っていません。「ファイル情報」というローカル変数については[別の記事](https://qiita.com/mylifewithviolin/items/a941fddb20acacbe58e6)で解説します。

# Mindプログラムソース
```mind:iseof.src
サンプル物理ファイルパスは　文字列定数　"c:\developments\vscode\mind9\sample.txt"。
サンプルファイルは　        ファイル。

サンプルファイルをオープンするとは　（・　→　・）
    サンプルファイルを　サンプル物理ファイルパスで　オープンし
    エラー？
    ならば　「サンプルファイルのオープンに失敗しました。（」を　表示し
    　　　　エラー文字列を　表示し　「）」を　一行表示し
            実行終わり
    つぎに
    「サンプルファイルをオープンしました。」を　一行表示すること。

サンプルファイルを一行読み出してデータ終り？とは　（・　→　文字列、真偽）
    サンプルファイルを　一行読み出し
    サンプルファイルが　データ終り？。

サンプルファイルをクローズするとは　（・　→　・）
    サンプルファイルを　クローズし
    「サンプルファイルをクローズしました。」を　一行表示すること。

メインとは　（・　→　・）
    
    サンプルファイルをオープンし

    ここから
        サンプルファイルを一行読み出してデータ終り？
        ならば　　　　捨てて　打ち切り
        さもなければ　ダブルクオートで囲んで表示し　改行し　
        つぎに
    繰り返し

    サンプルファイルをクローズすること。
```
ローカル変数「ファイル情報」を使わず「一行読み出してデータ終り？」をライブラリ単語化したので、グローバル変数の論理ファイル名で装飾しています。
