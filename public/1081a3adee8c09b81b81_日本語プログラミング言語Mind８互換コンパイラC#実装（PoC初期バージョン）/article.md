# はじめに
Mindのランタイム中間コードは非常に実装言語（や走行環境）と疎のつくりになっているので原理的にはC言語以外でも走行系の実装を実現可能で、現在C#とJavaとZig環境で走行させる事案が進行中です[^1][^2][^3]。中間コードは生成されたコンパイラの実装言語も実行ディスパッチャの実装言語にも依存しないため、本記事ではその動きと対をなすMindソースから中間コードを生成するC#互換コンパイラ（PoC/概念実証版）を実装します。


# 日本語プログラミングMind（マインド）とは
プログラミング言語Mind（マインド）は自然な日本語で記述できるスタック指向の軽量中間コードコンパイラ言語です[^4]。単語間の分かち書きが必須であくまで形式言語ですが、逆ポーランド記法[^5]で分かち書きされた日本語単語の語順が自然と日本語の語順となる「自然さ」で書くことができます。実装言語はCまたはTcl/Tk、Mind自身。

# Mind８互換コンパイラ実装案

この互換実装はCまたはMind自身で書かれたコンパイラロジックを独自のロジックで書き換えるものです。当面の実装言語はC#またはJavaです。本記事は先行しているC#互換実装です。Mindソースから生成されるmcoが互換となる以外、コンパイルロジックは公式コンパイラと異なります。

最初のPoCではいくつかのサンプルソースコードがコンパイルでき、生成されるmcoも純正コンパイラが生成されるconsoleのサブセット状態です。（本記事ではcompact方式と呼称します。）

コンパイラ本体はコマンドライン実行プログラムCLIから分離し、ソース解析からMCOイメージ生成までをライブラリAPIとして提供します。CLIはそのAPIを呼び出して入出力と診断表示を担当します。[^6]


互換コンパイラが生成したmcoファイルは、C言語で実装された公式ディスパッチャでも動くことをめざすものです。また、前記各言語による互換ディスパッチャで原理的に動作することを想定します。ただし、公式ディスパッチャが想定する全中間コードをコンパイルできない状態の場合はC#互換ディスパッチャでも動作検証します。

## 構成

日本語プログラミング言語あおい（Aoi）コンパイラの「ライブラリによる解析・生成」と「薄いCLI」の分離を参考にしています。

```text
Rmind8Compiler.slnx
  src/
    Rmind8.Compiler.Core/      # 字句・構文・意味解析、IR、MCO生成、診断
    rmind8c/                   # consoleアプリ。引数、ファイルI/O、診断表示
  tests/
    Rmind8.Compiler.Tests/     # 単体・ABI・受け入れテスト
    fixtures/                  # ソース、期待診断、基準MCOまたは実行結果
```

### Core API案

```csharp
public sealed record CompilationDiagnostic(
    string Code, DiagnosticStage Stage, string SourceName, int? Line, int? Column, string Message);

public sealed record CompilationResult<T>(
    T? Value, IReadOnlyList<CompilationDiagnostic> Diagnostics)
    where T : class;

public sealed class Rmind8Compiler
{
    public CompilationResult<McoImage> Compile(
        string source, string sourceName, McoTargetProfile target);
}
```


PoCのターゲットはconsoleに固定しています。未指定時に異なるABIを暗黙選択せず、明示された非対応ターゲットは使用方法エラーにします。出力先と同じディレクトリに一時ファイルを作り、コンパイル成功後に置換することで、失敗時に既存MCOを壊さないようにします。

## コンパイルパイプライン

※互換コンパイラC#実装のコンパイルパイプラインの実装構成は公式Mind８コンパイラの実装とは大きく異なります。

1. **ソース入力**: 既存コンパイラが受け付ける文字コード、改行、ファイル分割・インクルード規則を確認する。文字コードを明示してデコードし、未対応文字やデコード失敗を診断する。
2. **字句解析**: Mindの予約語、識別子、数値・文字列リテラル、コメント、区切り記号をトークン化し、各トークンに行・列を付ける。
3. **構文解析**: PoCの対応構文をASTへ変換する。構文木の段階で未対応構文を明確に拒否する。
4. **意味解析**: 語・変数・定数・ラベルを解決し、型やスタック効果、参照先、データサイズを検査する。C語の呼出しはコンソールABIプロファイルに存在する番号のみ許可する。
5. **IRとリンク解決**: ラベルを持つ命令列、データ領域、Mind単語LOC、スタック要件を保持するIRを作る。分岐先等の未確定参照を一括解決し、オフセット範囲と命令境界を検証する。
6. **MCOエンコード**: ABIに定められたバイト順・ワード幅でMコード、LOCテーブル、固定長メタデータを直列化する。サイズ・オフセットのオーバーフロー、上限超過、未解決ラベルを出力前に検出する。
7. **CLI出力**: Coreの成功結果のみを書き出し、診断は標準エラーへ、終了コードは成功0／失敗非0とする。

## compact方式でサンプルをコンパイル

**compact方式とは:** 純正consoleライブラリをリンクせず、C#互換コンパイラが対応するソースから、必要な命令・変数領域と最小限の起動／終了処理を持つ小さいMCOを直接生成します。純正コンパイラは不要ですが、純正MCOと同じバイト列を再現する方式ではなく、実行結果の互換性を目指すものです。現在は5サンプルに対応するものの、Mind言語全体への対応を保証していません。

**ローカル変数サンプル**

```powershell
dotnet .\src\rmind8c\bin\Debug\net10.0\rmind8c.dll `
    --backend csharp --target mind8-console `
    .\tests\fixtures\variables.src .\artifacts\v5-samples\compact\variables.mco
if ($LASTEXITCODE -ne 0) { throw 'variablesのcompact生成に失敗しました。' }
```

# おわりに

## Mind８互換コンパイラC#実装のライセンスの注意事項
Mindバージョン８（以下Mind８）は長らくフリーソフトとして公開されていましたが、Mindバージョン９（以下Mind９）からは基本機能は無償のままGUIライブラリと今後リリースされるいくつかのライブラリは有償オプションとなっています。また、それに伴いMind９のソースコードの扱いもライセンスが変更されています。本件はソースコードの扱いがMind８の契約条件に基づくもので、さらに著作権者の @killyさんの許諾のもとに進めております。
まだPoC／概念実証版の状態で詳しい準拠ライセンス未定ですが、基本的に無保証です。
