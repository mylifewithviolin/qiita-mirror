# はじめに
日本語プログラミング言語Mindの小技「空白？」について説明したいと思います。

# 対象読者
日本語プログラミング言語Mindのユーザー、または日本語プログラミング言語に興味のある方

# この小技に関連するMind言語マニュアル

この小技に関連するMind言語仕様の記述はMind8プログラミングマニュアルに記載があります。
７ 文字列操作
└文字列を調べる機能
　└文字コードを調べる単語

>構文＝　＜文字＞が　空白？　→　＜真/偽＞
>
>　文字が空白、カンマ、読点などの空白文字（区切り文字）であることを調べる。カンマ／読点は、半角／全角のどちらでもよい。また、半角空白（十六進で20H）未満の、いわゆる制御コードも空白とみなす。


本機能（本記事）は、下記のバージョンに対応しています。Mind８のLinux版も対応していると思いますが、本記事では特に検証を行っておりません。

# 対応バージョン

■Windows版　□Linux版

# 小技の解説
「空白？」はMindの文字コード判定機能の１つです。

他のプログラミング言語の場合（静的型付けシステムの場合）、文字と文字列の違いは型の違いとなっている場合（例えばChar型のようなものと可変長文字列型のString型のようなもの）がありますが、Mindの場合も、1文字の文字を「文字」、２文字以上の文字列を「文字列」としており、1文字だけの文字型というもの（たとえばChar型のようなもの）はないのですが、Mindの処理単語の中には１文字の文字を文字コードすなわち数値型として扱うものがあります。

この「空白？」もそのひとつです。

まずは公式マニュアルでの解説をひも解きながら補足説明します。

７ 文字列操作
>Mindでは 文字 と 文字列 という２つの用語をはっきりと使い分けている。

これは１文字の文字に対して文字コード型Charのようなものがあるという意味ではないとわたしは解釈しています。実際の定義を見た感じ、文字を文字コードとして扱う場合は数値型の定数、変数として宣言します。

７ 文字列操作
└文字

>まず、Mindでいうところの「文字」とは、独立した１つの文字のことを表す。そして、その１つの文字は、その文字に割り当てられた文字のコードとして評価される。つまり、最終的には、文字は数値と同じ扱いになる。

１文字の文字列定数として宣言した場合と、１文字を数値（文字コード）として宣言した場合では、処理単語が想定している型チェックにひっかかってコンパイルエラーとなる場合があります。「空白？」が想定しているのは文字コード（数値）の変数です。

以下にMindが空白文字と認識する文字（文字コード）をまとめました。
(Windows版・SJIS）

| 文字名 | 16進コード | 備考 |
|:-|:-:|:-|
| 全角空白 |0x8140|「　」   |
| 全角読点 |0x8141|「、」   |
| 全角カンマ |0x8143|「，」|
| 半角空白 |0x20|「 」   |
| 半角カンマ |0x2C|「,」   |
| 制御コード |0x00～0x1F|   |
 
# Mindプログラムソース

```mind:isspace.src
※全角空白は　定義済    　数値　　'　'。

※半角空白は　定義済    　数値　　' '。
半角カンマは　         　数値　　','。

※以下の制御コードは定義済
※ＮＵＬは　　　　　　　　数値　　00H。
※ＢＥＬは　　　　　　　　数値　　07H。

※ＣＲは　　　　　　　　　数値　　0DH。
※ＬＦは　　　　　　　　　数値　　0AH。
※ＦＦは　　　　　　　　　数値　　0CH。
※ＥＳＣは　　　　　　　　数値　　1BH。

制御コードは空白扱いですよとは　　（数値　→　・）

    制御コードに　入れ

    ならば

    つぎに。

    「半角カンマは空白扱いです。」を　一行表示し　つぎに、

```
「空白？」が扱う変数を数値として定義しています。文字列として定義した場合の例は後述します。

文字コードを数値として定義する場合、「数値」と宣言した後、' 'で該当文字を囲って数値とすることができます。

制御コードの例はMindで定義済のものを引用しました。0x20H以上の制御コードとして「ＤＥＬ」0x7FHを定義しています。これは空白とは判定されない制御コードです。
