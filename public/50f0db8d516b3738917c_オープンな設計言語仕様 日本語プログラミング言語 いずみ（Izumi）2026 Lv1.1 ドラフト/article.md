# はじめに
日本語プログラミング言語あおい（Aoi）の実装言語仕様2025 Lv1.2を生成AIに読み込ませて仕様駆動開発を展開し、2026 Lv1.3（で確定した範囲の一部）で最小MVPの開発を完了しました。これに伴いコンパイラ言語いずみ（Izumi）の開発を加速させるべく、いずみ仕様2026 Lv1.0のAIレビューを実施し内部仕様を再構成しました。

# 概要
日本語プログラミング言語いずみ（Izumi）（開発コード名 日本語ロジック仕様記述言語Re:Mind）はオープンな設計言語仕様で[^1]、どなたでもこの記法を使いロジックを記述することができます。

# 日本語プログラミング言語いずみ（Izumi）とは
いずみ（Izumi）はシステムエンジニアなどソースコードを直接生産しない職種の方々が、自ら考案したロジックをコンパイル検証するためのコンソールアプリベースのコンパイラ言語となります。

制御構文の開始シンボルとして、◇、〇、・、□などの全角記号を用い、箇条書きされた日本文としての体裁を[日本語プログラミング言語あおい三姉妹](
https://qiita.com/mylifewithviolin/items/9749c4942748b3a743d6)で共有しています。

ターゲット言語実行系のライブラリは基本的にサポートせず、あくまでロジックの検証用にコンソール出力の実行コードを生成するものとなります。ただし、近い将来データベース照会言語は一般的なSQL文記述で実行可能な状態をサポートする予定です。（このバージョンでの言及はありません。）



# 日本語プログラミング言語 いずみ（Izumi）仕様 2026 Lv1.1 ドラフト

> 本書は、[いずみLv1.0](./日本語プログラミング言語%20いずみ言語仕様2026%20Lv1.0.md)を置き換えて確定する文書ではなく、実装前に補足・決定する事項を整理するドラフトです。Lv1.0の構文イメージを維持しつつ、あおいで採用済みの規則を基本的な同期先とします。いずみ固有の選択案、およびあおい側でも未確定の細部は、確定事項と区別して記載します。

## 1. 目的と位置付け

いずみ（Izumi）は、日本語でロジックを記述し、コンソールアプリケーションの実行またはあおい（Aoi）への変換に用いる静的型付け言語です。本書の「Lv1.1」はいずみの版を示し、あおいの版番号とは同期しません。Re:Mindは言語ファミリーの旧称・開発上の呼称であり、いずみの別名として構文規則には使用しません。

以下の表示を使います。

| 表示 | 意味 |
|---|---|
| **同期案（あおい採用事項）** | あおいの採用済み規則と意味を合わせる提案です。いずみへの正式適用は確認が必要です |
| **既決定（実装前確認事項）** | Q01〜Q12で選択された方針です。詳細が未確定の場合はその旨を示します |
| **いずみ固有の推奨案** | いずみの既存構想に対する提案で、確定事項ではありません |
| **要決定** | 互換性のある実装に必要ですが、根拠資料では決定されていない事項です |
| **対象外** | 本ドラフトで受理範囲に含めない機能です |

### 1.1 対象とターゲット

Lv1.0ではC#・Java・Go・Zigをコンパイル先候補とし、C#をMVP対象としていました。本ドラフトでは、C#を実装・受入の初期対象、JavaをCLIで明示選択する変換対象、Go・Zigを将来の候補として扱う案を示します。Go・Zigへの変換は、各構文を同じ意味で表現できることが確認できない限り受理しません。

**要決定:** Javaへの直接コンパイルと、あおいへの変換後にJavaを生成する経路の対応範囲、Go・Zigの適合プロファイル、対象SDK・実行環境を確定する必要があります。

### 1.2 ターゲット中立性

**同期案（あおい採用事項）:** 同一プロファイルで受理されたソースは、ターゲット間で同じ意味を持つものとします。ターゲットが構文を表現できない場合、ターゲット固有動作へ黙って置き換えず、生成前に診断します。ターゲット固有機能は明示した拡張に限ります。

いずみはImportを受理しないため、利用者の通常ソースにターゲット言語固有の型名・構文を直接書かない方針とします。

## 2. 字句規則

### 2.1 文字、改行、空白

**同期案（あおい採用事項）**

- 入力は厳密なUTF-8です。不正なUTF-8はエラーとし、置換して続行しません。UTF-8 BOMはファイル先頭にある場合だけ除去できます。
- 改行はLFまたはCRLFです。物理改行は単純文の終端です。括弧内・文字列リテラル中の改行は認めません。
- 半角空白、全角空白、タブはトークン区切りとして扱います。インデントはブロック境界を定めません。
- キーワードと隣接識別子はトークン境界で区別します。空白を省略できる形は、文法に列挙したものに限ります。
- 識別子の比較は入力されたUnicodeコードポイント列で行い、Unicode正規化や大文字・小文字変換を行いません。

**記号のコードポイント案**

| 記号 | コードポイント | 用途 |
|---|---|---|
| `▽` | U+25BD | 関数・クラス宣言の開始 |
| `△` | U+25B3 | 関数・クラスの終端 |
| `□` | U+25A1 | 実行文の開始 |
| `◇` | U+25C7 | 分岐の開始・節 |
| `〇` | U+3007 | 繰り返しの開始・終端 |
| `・` | U+30FB | 変数・定数宣言 |

類似文字（例：`○` U+25CB、半角中点 `･`）は代替記号として扱いません。

**要決定:** Unicode文字・数字の判定に用いるUnicode版と、識別子に含める文字カテゴリ（結合文字、長音符、その他記号等）を固定してください。出力先予約語一覧と対象言語バージョンも規定してください。

### 2.2 コメント

**同期案（あおい採用事項）:** `//` は行末まで、`/* ... */` は閉じ記号までのコメントです。ブロックコメントは入れ子にせず、閉じ忘れは位置付きエラーとします。文字列内のコメント記号はコメント開始として扱いません。

**既決定（Q07）:** いずみではJavaDoc形式の英字名を手書きしません。`/** ... */` の要約行・タグを名前変更には使用しません。あおい出力時は日本語名から仮英字名を生成し、出力されたあおいソース上で変更します。

**要決定:** `/** ... */` を通常のブロックコメントとして無視するか、使用自体を診断するかを確定してください。仮英字名の形態素解析・文字変換・衝突回避は決定的かつ再生成可能でなければなりませんが、具体的なアルゴリズムは別途実装仕様として固定してください。

## 3. 型・宣言・名前解決

### 3.1 基本型

**既決定（Q08）:** 型名は共通の基本型ホワイトリストに限定し、未知の型を暗黙に読み替えません。型名一覧は次のとおりとする案です。

| いずみの日本語型名 | 許可するあおい論理型名 | 意味 |
|---|---|---|
| `整数` | `int` | 符号付き32ビット整数 |
| `文字列` | `string` | null非許容文字列 |
| `ブール値` | `bool` | 真偽値 |

日本語型名と対応するあおい論理型名は同じ型を表します。`Integer`、`String`、`boolean`、`long` 等のターゲット固有名・一覧外の型名はエラーです。定数・変数・関数の引数と戻り値には、この表の型名のみ使用できます。クラス型が利用できる範囲は8章によります。

`null` リテラル、nullable型、暗黙の数値変換、暗黙の文字列化は受理しません。明示的変換を導入する場合は、その構文と各ターゲットでの意味を別途定義します。

### 3.2 変数・定数

変数宣言は `・型名 名前` または `・変数 型名 名前`、定数宣言は `・定数 型名 名前 = 式` を基本形とします。宣言での `変数` キーワード省略は同じ意味です。初期値を省略できるか、許される初期値の式範囲はプロファイルで明記します。

**同期案（あおい採用事項）:** 名前は宣言位置以降の同一ブロック内で有効です。同一スコープの重複宣言はエラーです。定数は再代入できません。MVPではローカル変数・定数に初期値を必須とし、定数初期値は基本リテラルに限ります。

**要決定:** 初期値なしの変数、フィールドの初期値、内側スコープでの名前の再宣言、ブロックを作る構文の範囲を明確にしてください。

## 4. 式・演算子・型検査

### 4.1 同期する演算と意味

**同期案（あおい採用事項）**

| 分類 | 記法 | 規則案 |
|---|---|---|
| 整数算術 | `+ - * / %` | 32ビット整数演算。除算は整数除算で、端数はゼロ方向に切り捨てます |
| 整数比較 | `< > <= >= == !=` | 整数同士に限ります |
| 等価比較 | `== !=` | 同じ基本型の値に限ります。文字列は序数による値比較です |
| 論理演算 | `! && ||` | bool型に限り、`&&` と `||` は短絡評価です |
| リテラル | 十進整数、二重引用符文字列、`true`、`false` | 文字列エスケープは `\\`、`\"`、`\n`、`\r`、`\t` のみです |

文字列の大小比較、未定義エスケープ、nullリテラル、暗黙変換、未対応型との演算は診断します。ゼロ除算は実行時エラーです。整数オーバーフローの結果はターゲット間の同一性を保証しません。

### 4.2 未確定の演算子細則

**要決定:** あおいのLv1.4レビューでも演算子優先順位・結合規則とリテラル境界が未確定とされています。いずみでも、実装前に少なくとも以下を表として固定してください。

- 単項演算子、乗除算、加減算、比較、等価、論理積、論理和の優先順位と結合性
- 比較演算子の連鎖を許すか
- 整数リテラルの範囲、桁区切り、符号の字句解釈
- 文字列中の生改行・制御文字、不正エスケープの扱い
- オーバーフローを未規定として許すか、実行時検査を要求するか

優先順位を決めるまでは、複合式をあおいへ出力してターゲット言語の優先順位に依存させてはいけません。変換器は構文木の意味を保つ括弧を出力する必要があります。

## 5. 関数・実行文・戻り値

### 5.1 関数宣言と呼び出し

関数宣言は `▽[戻り値型] 関数名(型 引数, ...)` で開始し、`△` で終了します。角括弧内の戻り値型は省略可能です。戻り値型を省略した宣言は値を返さない関数を表し、`void` を明記した宣言と同じ意味です。値を返さない関数では戻り値型の省略と `void` の明記のどちらも認め、戻り値のある関数では戻り値型を必須とします。引数のない関数は `()` を記述します。呼び出し側では型名を記述せず、位置引数として式を渡します。

```aoi
▽得点を表示する(整数 得点)
    □コンソール.一行表示する(得点)
△

▽void 名前を表示する(文字列 名前)
    □コンソール.一行表示する(名前)
△
```

上の2つの宣言はいずれも戻り値のない関数です。`void` を省略する場合も、引数リストの括弧は省略しません。

**同期案（あおい採用事項）**

- 関数名は同一プログラム内で一意とし、オーバーロードを認めません。
- 関数呼び出しの引数には、型が一致する式を指定できます。関数呼び出しを式の一部として使用できます。
- 再帰を許可し、関数シグネチャを本体解析前に登録することで宣言順に依存させません。
- 参照渡し、既定値引数、可変長引数は対象外です。

通常の呼び出し形は `□関数名(式, ...)` とします。Lv1.0にある `□(式, ...)で 関数名` 形式を互換構文として残す案です。この形式は助詞を `で` に固定し、解析後は通常の関数呼び出しと同じ意味にします。`を`、助詞なしの後置名、助詞と関数名が曖昧になる形は受理しません。

**要決定:** 後置形式をLv1.1で正式に受理するか、通常形に限定するかを選択してください。いずれの場合も文法にない呼び出し形式は診断します。

### 5.2 実行文とreturn

`□` の後に許す実行文は、代入、関数呼び出し、戻り値、ループ制御に限定します。一般式文は受理しません。

**同期案（あおい採用事項）:** returnの正規形は `□式を 返す` です。既存の互換形 `□式 を 返す` と `□return 式` も同じ意味として受理できます。値を返す関数はすべての実行経路で型一致する値を返し、値を返さない関数では値を返しません。返却漏れは意味解析エラーです。

例:

```aoi
▽整数 年齢を取得する()
    □年齢 を 返す
△
```

上例では `年齢` が有効なフィールドまたは変数として宣言されている必要があります。実際の例では、宣言・スコープが明らかになるよう定義を併記します。

**要決定:** 「すべての経路」の制御フロー判定、到達不能文の診断、値を返さない関数の明示的returnの可否を定めてください。

## 6. ブロック・分岐・繰り返し

### 6.1 ブロック境界と終端

ブロックの対応はインデントではなく開始記号・節・終端記号のスタックで検査します。重複・異種・不足終端や曖昧な省略は構文エラーです。

**既決定（Q01）:** 終端の省略は、許可する構文・位置を一覧に限定し、一覧外では明示終端を必須にします。曖昧な省略はエラーです。Lv1.0に明記された省略可能位置を許可表に載せる必要があります。

| ブロック | 明示終端 |
|---|---|
| 関数・クラス | `△` |
| 条件分岐 | `◇ここまで` |
| ループ | `〇ここまで` |

**同期案（あおい採用事項）:** あおい出力では終端を省略せず、各構文の明示終端を出力します。いずみ入力で許可された省略形は、ブロックスタックから一意に境界を決定できるものだけ受理し、あおい出力時に明示形へ正規化します。

**要決定:** Q01に基づく省略許可表を作成してください。表が確定するまでは、あおい互換性を優先し終端省略を認めない案を推奨します。

### 6.2 条件分岐

基本形は `◇条件 の場合`、任意の `◇他に`、`◇ここまで` とします。条件はbool型です。入れ子を許可し、各ブロックの節と終端を対応付けます。1行条件文は構文表で明示的に許可されない限り受理しません。

**要決定:** `◇他に 条件 の場合` を許可するか、許可する場合の節順と終端規則を定めてください。空白を省略できる位置も文法に列挙します。

### 6.3 繰り返しとループ制御

**同期案（あおい採用事項）:** 条件形式は前判定ループとし、条件は各反復の前に評価されるbool式です。条件が偽なら本体は実行されません。`□脱出する` と `□ループ先頭へ` をループ制御の正規形とします。いずれも最も内側のループを対象とし、ループ外で使用した場合はエラーです。

Izumiにあるカウンタ式 `〇初期化, 条件, 更新 繰り返す` はいずみ固有の拡張案です。意味は「初期化を一度実行し、条件判定、本体、更新を繰り返す」とします。`□ループ先頭へ` は更新式を実行してから次の条件判定に進むものとします。

**要決定:** カウンタ変数の型（整数を推奨）、新規宣言・既存変数の扱い、スコープ、初期化・条件・更新の省略、更新式の文法、条件式の括弧、無限ループの記法を確定してください。無限ループと後判定ループはMVPの共通範囲に含めない案です。

## 7. クラスとインスタンス

### 7.1 構文と修飾子

**同期案（あおい採用事項）**

- クラスは `▽クラス クラス名`、継承は `▽クラス クラス名 : 基底クラス名` とします。継承記号は半角 `:` です。
- `static` を指定したメンバーは型に属し、`instance` を指定したメンバーはインスタンスに属します。どちらも省略した場合は `instance` とします。
- 省略可能な終端は許可表に限り、ターゲット言語ごとの推測をしません。

**いずみ固有の推奨案:** クラスは層1（継承なし）と層2（継承あり）に分け、対象ターゲットが層に対応しない場合は生成前にエラーとします。初期適合ターゲットはC#・Javaとし、Go・Zigでクラス相当の意味を定義するまではクラス構文を拒否します。

**要決定:** クラス宣言・メンバー・アクセス修飾子の必須性と省略時の可視性、フィールド初期値、コンストラクタ、基底コンストラクタ呼び出し、override・隠蔽、循環継承、クラス型の引数・戻り値を定めてください。修飾子順序とメンバー種別ごとの許可組合せも必要です。

### 7.2 インスタンス生成

生成式は `new()` または `new(引数...)` とし、対象型を左辺の宣言型から解決する案です。型が一意に決まらない場合はエラーとします。

**要決定:** コンストラクタ宣言と引数解決の正式文法が定まるまでは、引数付き生成を受理しない案です。

## 8. エントリーポイント

**既決定（Q06）:** 入口名は `main` とし、大文字小文字を区別します。入口は最大1つです。入口がなければライブラリを生成し、入口があれば実行物を生成します。重複入口と非対応署名はエラーです。

入口のターゲット固有形式は生成器が出力し、利用者ソースの意味をターゲット別に変えません。

**要決定:** `main` のトップレベル／クラス内の配置、アクセス修飾、引数、戻り値を決定表にしてください。暫定推奨は、トップレベルの引数なし・値を返さない関数を入口とすることです。対応するターゲットでは、生成時に必要なクラスやランタイム引数配列を補います。トップレベル文は受理しない案です。

## 9. いずみからあおいへの変換

**既決定（Q10）:** 生成するImport／Aliasは現行あおい文法に適合させ、生成物をあおいCLIで再解析・コンパイルできることを契約とします。あおい側の文法拡張を前提にしません。

**同期案（あおい採用事項）:** あおいMVPには `コンソール.一行表示する(string|int)` が組込み関数としてあります。したがって、同じ機能を実装するためのImport／Aliasを重複生成せず、組込み呼び出しへ変換する案です。null、bool、未対応型を出力引数に渡す場合はエラーとします。

その他のターゲットAPIを利用する構文は、いずみ側でImportを導入しない限り受理しません。将来Aliasを出力する場合は、あおいの各ターゲット向け定義と論理シグネチャが一致することを検証します。

**要決定:** 組込み関数と生成Aliasの重複を避ける方針を確認し、C#・Java向けの生成物を実際のあおいParser・生成器で検証してください。Javaの型名等をあおいAliasへ埋め込む場合は、現行のAlias仕様に適合するか個別に確認します。

## 10. コンソール出力

**既決定（Q09）:** `コンソール.一行表示する` は予約機能です。引数は1つで、`文字列` または `整数` に限ります。null、未対応型、予約名・予約シグネチャとの衝突は診断します。ターゲット間で値の出力結果を一致させます。

bool値を出力する機能は対象外です。必要な場合は、明示的な文字列変換機能を別途定義します。

## 11. CLI・生成物・診断

### 11.1 CLI

入力ファイルの拡張子は `.izm`、出力ベース名は拡張子なしとします。オプションは大文字・小文字の扱いを含めて定義し、未知オプション・値なし・過剰引数をエラーにします。

**既決定（Q05、Q11）**

- C#／Javaの選択はCLIオプションで明示し、拡張子から推測しません。
- コンパイルオプションは結合形・分離形の両方を受理します（例：`-cc` と `-c c`）。
- あおい変換オプション `-ta` とターゲット選択を区別します。
- 競合するオプション値はエラーとし、黙って上書きしません。

CLIの形の案:

```text
izumi sourceFile targetBase [-c c|j] [-t a]
```

上記のオプション名・値は、Q05・Q11の方針を具体化する提案であり、最終確定ではありません。`-c` を省略したときの既定ターゲット、`-c` と `-t` の併用可否、同じ値の重複指定、生成ファイル名と配置規則を確定してください。

### 11.2 成果物保護

**既決定（Q12）:** 生成物一式を一時領域で生成・検証し、成功時に配置を入れ替えます。失敗時は既存成果物を保護し、途中生成物で既存ファイルを壊しません。実行物からライブラリへの切り替え時に削除できるファイルは、コンパイラが所有する成果物と特定できるものに限ります。

SDK・Runtime・host packの要件を明示し、必要な環境がない場合は不完全な実行物を作らず診断します。OS・.NETバージョン・配布形態は未確定です。

### 11.3 診断と適合性

**同期案（あおい採用事項）**

- 失敗時は診断を標準エラーへ出力し、非0で終了します。
- 解析・意味解析・生成に失敗した場合、出力成果物を新規作成せず既存出力も変更しません。
- 診断位置は行・列を含めます。行・列は1始まり、列はUnicodeコードポイント単位とし、タブは1文字として数える案です。
- 正常系・異常系を構文単位の適合テストで固定します。ターゲット間の標準出力比較では、LF/CRLFと行末空白の正規化を行い、不正UTF-8は入力時に拒否します。

**要決定:** 複数診断の継続条件、警告とエラーの区別、診断コード・メッセージ形式、標準出力の文字コード、最終改行の比較、実行時エラーの契約を確定してください。上記の列番号規則はあおいレビューでも「対応表案」の状態であり、いずみでは推奨案です。

## 12. 受理範囲と対象外

初期の共通コアに含める案は、変数・定数、`int` / `string` / `bool`、式、関数、明示的な分岐と前判定ループ、コンソール出力です。C#実行物とあおい変換を優先して受入し、他ターゲットは同じ意味を保持できる構文のみ受理します。

次の機能は、本ドラフトでは受理範囲に含めません。

- Import、任意のターゲットAPI・物理型名
- null、nullable型、暗黙変換、文字列連結・暗黙の文字列化
- 配列、例外、switch、無限・後判定ループ
- 参照渡し、既定値引数、可変長引数、オーバーロード
- JavaDocコメントによる名前変更、明示的な英字名指定
- 文法・意味が確定していないクラス／継承／コンストラクタ機能

## 13. Lv1.1確定前に決定する事項

1. 字句規則のUnicode版・識別子文字カテゴリ・予約語一覧。
2. EBNF等による全体文法、文の改行境界、空白省略規則、ブロック対応。
3. Q01に基づく終端省略許可表と、あおい出力での終端補完。
4. 演算子優先順位・結合性、整数・文字列リテラル境界、オーバーフロー契約。
5. 関数の後置助詞形式を残すか、return到達性とスコープ規則。
6. forカウンターの型・宣言・更新・評価順、ループ制御対象。
7. クラス・アクセス修飾子・コンストラクタ・継承とターゲットごとの層対応。
8. `main` の配置・署名決定表、CLIオプションの既定値と出力配置。
9. 仮英字名アルゴリズム、診断形式、適合テスト契約。
10. C#／Javaへの直接変換と、あおい経由変換のサポート範囲。

これらの選択を確定し、正常例・境界例・エラー例と期待結果を適合テストにした後、本ドラフトを仕様本文へ統合してLv1.1として確定します。
